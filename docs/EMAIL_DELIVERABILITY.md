# Email Deliverability and Anti-Spam Standards

This document specifies the deliverability architecture and anti-spam measures implemented across InvoiceUI to ensure all emails (Invoices, Payment Reminders, Authentication Magic Links, and Quotations) reliably reach client inboxes without being flagged by spam filters.

---

## 1. Technical Anti-Spam Measures in Code

### RFC 5322 Friendly Sender Display Names
- Sending from bare email addresses (e.g. `billing@domain.com`) triggers phishing and spoofing filters.
- All system emails use `formatSenderFrom(displayName, sendingAddress)`:
  - **Invoices and Reminders**: `"${business.name} via InvoiceUI" <${env.EMAIL_FROM}>`
  - **Magic Link Authentication**: `"InvoiceUI Security" <${env.EMAIL_FROM}>`
- A legitimate `Reply-To` address is always set (pointing to the business billing contact or owner email) to satisfy heuristic checks in Gmail and Outlook.

### Transactional & Loop Suppression Headers
All Resend transmissions include headers generated by `getDeliverabilityHeaders()`:
- `Auto-Submitted: auto-generated`: Declares the message as automated transactional communication to prevent automated out-of-office auto-responder loops.
- `X-Auto-Response-Suppress: OOF, AutoReply`: Explicit instruction to Microsoft Exchange / Office 365 servers to suppress vacation auto-replies.
- `X-Entity-Ref-ID`: Unique tracking and reference header (`invoiceui/${ownerId}/${messageId}`) for mailbox threading and server reputation.

### Unsubscribe Headers for Payment Reminders
- Google and Yahoo 2024 sender rules penalize any sender with a spam complaint rate exceeding 0.1%.
- If recipients cannot easily manage or pause automated reminders, they click "Report as Spam", degrading domain reputation.
- Automated payment reminder emails include:
  - `List-Unsubscribe: <mailto:${business.email}?subject=Unsubscribe%20Invoice%20Reminders%20${invoiceNumber}>`
  - `List-Unsubscribe-Post: List-Unsubscribe=One-Click`
  - Clear in-footer opt-out and support contact instructions.

### Hidden Anti-Spam Preheaders
- Without an explicit preheader, email clients scrape the first visible text or alt tags in the HTML, often displaying broken fragments or CSS comments in the inbox preview snippet.
- Every HTML template incorporates an invisible preheader snippet followed by zero-width non-breaking space padding (`&#847;&zwnj;&nbsp;...`) to prevent subsequent markup from leaking into the preview line.

### CAN-SPAM, UK PECR, and GDPR Compliant Footers
Spam scoring engines (like SpamAssassin rule `MISSING_PHYS_ADDR`) penalize commercial emails that omit a physical postal address. Every email generated by InvoiceUI includes:
1. **Physical Postal Address**: The registered business address formatted on a single clean line (`formatAddress(b)`).
2. **Transactional Reason Notice**: Explicit explanation of why the recipient received the email (e.g. active service agreement, invoice review, or account sign-in).
3. **Recipient Address Transparency**: Shows `Sent to: recipient@example.com` to confirm legitimate targeted delivery.
4. **Multipart/Alternative Parity**: Both HTML and plain-text counterparts include the exact same sender, address, and reason information to ensure a 0 score for SpamAssassin `MPART_ALT_DIFF`.

## 2. DNS Configuration Checklist (Domain Authentication)

To achieve 10/10 deliverability on your custom sending domain (configured via `env.EMAIL_FROM`), configure the following DNS records in your domain registrar (e.g. Cloudflare DNS):

### SPF (Sender Policy Framework)
Authorizes Resend servers to send emails on behalf of your domain.
- **Type**: `TXT`
- **Name**: `@` (or subdomain, e.g. `mail`)
- **Content**: `v=spf1 include:resend.com ~all`

### DKIM (DomainKeys Identified Mail)
Cryptographically signs outgoing messages to prove they have not been altered in transit.
- Resend provisions three `CNAME` records with unique selector keys upon adding a domain in the Resend dashboard.
- Add all three `CNAME` records with DNS proxying disabled (DNS-only / Grey cloud in Cloudflare).

### DMARC (Domain-based Message Authentication, Reporting, and Conformance)
Specifies domain policy for emails failing SPF or DKIM checks.
- **Type**: `TXT`
- **Name**: `_dmarc`
- **Content**: `v=DMARC1; p=quarantine; pct=100; rua=mailto:dmarc-reports@yourdomain.com`

## 3. Deliverability Verification Workflow

When verifying email deliverability:
1. **Send Test Invoices**: Use the "Send invoice" action modal to review the "Spectacular HTML preview" tab.
2. **Check Inbox Preview**: Confirm that the preheader snippet appears cleanly in Gmail or Apple Mail without alt text spill.
3. **Check Deliverability Headers**: In receiving mail clients, select "Show Original" or "View Message Details" to verify `Auto-Submitted`, `X-Entity-Ref-ID`, and DKIM passing statuses.
